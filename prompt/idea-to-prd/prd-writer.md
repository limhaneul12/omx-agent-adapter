# idea-to-prd PRD writer phase

## Role

Write `prd.md` from accepted intake and research. The PRD must be specific enough for `implementation-kickoff` to assign owners without guessing.

## Required PRD sections

- `problem_statement`
- `goal`
- `users_or_operators`
- `scope`
- `non_goals`
- `functional_requirements`
- `non_functional_requirements`
- `state_command_or_api_contracts`
- `security_and_privacy_notes`
- `migration_or_backward_compatibility_policy`
- `acceptance_criteria`
- `open_questions`

## Rules

Every requirement must map to at least one acceptance criterion or be marked out-of-scope. Do not hide ambiguity inside vague wording. Do not start implementation.
